# GameHall

**好友棋牌桌游馆 · 八款游戏 · 浏览器即开即玩**

![GameHall：好友棋牌桌游馆。](apps/web/public/og.png)

GameHall 是一个面向好友局的实时多人棋盘游戏平台。输入昵称，创建私人房间，把六位邀请码分享给朋友，就能通过浏览器开始对局。

服务端统一处理游戏规则、房间状态和断线恢复；单人模式提供电脑练习、残局闯关与 24 点挑战。

## 核心能力

### 好友房与实时对局

- **邀请码加入**：支持六位邀请码和 `?room=XXXXXX` 分享链接；只有 `room` 参数会预填邀请码。
- **完整房间流程**：入座、准备、开局、结算、房主重开；支持 2–4 人的玩法由房主在成员准备后开局。
- **明确的离房反馈**：主动离房返回大厅；房间被关闭或到期时显示提示。
- **房内消息**：支持快捷表情、短文本消息，并持久化最近消息。

### 可靠性与恢复

- **服务端权威状态**：回合、规则、胜负、版本和权限均由服务端校验。
- **重复与过期动作保护**：`actionId` 防止重复提交，`expectedVersion` 拒绝过期操作；确认超时后以原动作 ID 有界重试，并同步权威棋盘。
- **持久化恢复**：SQLite WAL、外键、事务和版本化迁移；断线及服务重启均有有限恢复窗口。
- **连接恢复**：WebSocket 不可用时尝试轮询，过期会话自动重建；网络恢复或页面唤醒时通过 `room:sync` 取得最新房间、游戏和消息快照。
- **清楚的回合提示**：区分当前回合、好友离线暂停、自己的连接恢复和操作确认中；自动重连耗尽后可点“重新连接”，连接期间不会重复发起。

好友离线导致的暂停无需手动重连。旧房间的迟到事件和操作回执会被忽略；同房间的新棋盘快照即使先到，也会等本次动作确认后再接受下一步。

### 界面与键盘操作

- **多种屏幕适配**：桌面、窄屏桌面、平板和手机均可创建或加入好友房；入房后焦点回到房间标题，终局结果与棋盘同时可见。
- **游戏发现**：八款游戏可搜索，支持短局、策略、多人和收藏筛选；卡片提供规则与大致时长，房间侧栏展示当前玩法规则。
- **本地收藏**：保存在当前浏览器；存储不可用时仍可临时使用。动画遵从系统减少动态效果设置。
- **键盘可用**：规则弹窗支持键盘操作；落子后轮到自己时可继续操作棋盘，Tab 离开后不会抢回焦点。
- **字体稳定加载**：界面使用同站 Noto Sans SC / Noto Serif SC 可变字体；现有界面文字由精简字库覆盖，其余常用汉字按需加载。字体下载期间先显示系统字体，不依赖外部字体样式请求。字库、许可和再生成方式见 [本地中文字体](docs/assets/local-fonts.md)。

| 棋盘 | 选择位置 | 确认动作 |
| --- | --- | --- |
| 点格棋 | 方向键选择空边 | Enter 或空格画边 |
| 四子连线 | 左右方向键跳过满列，Home / End 到首末可用列 | Enter 或空格投放 |

## 单人练习

从首页卡片或下表中的 URL 参数直接进入，无须昵称或实时连接。练习数据保存在当前浏览器，不创建好友房，也不写入 SQLite。

| 模式 | URL 参数 |
| --- | --- |
| 五子棋电脑练习 | `?practice=gomoku` |
| 四子连线电脑练习 | `?practice=connect-four` |
| 黑白棋电脑练习 | `?practice=reversi` |
| 点格棋电脑练习 | `?practice=dots-and-boxes` |
| 四子连线残局闯关 | `?practice=connect-four-puzzles` |
| 24 点单人练习 | `?practice=twenty-four` |
| 推箱子十关解谜 | `?practice=sokoban` |

### 电脑练习

- **自由设置**：四款棋类可选“轻松 / 认真”、自己或电脑先手；支持悔棋、重新开始和返回大厅。设置在明确重新开始后生效。
- **提示一步**：轮到自己时查看建议落点及原因，再选择采用、取消或自行落子；提示不自动落子，也不计入存档。
- **刷新续局**：自动保存当前棋局、实际设置和悔棋历史；刷新或返回后可继续。首页入口会随其他标签的进度更新。
- **多窗口冲突处理**：保留当前标签的棋盘，并排预览两盘差异，由玩家选择接着已保存的局面或保存当前棋局；离开不会覆盖另一窗口。
- **重开确认**：进行中的棋局已有落子时，重开需确认；Esc 或点击背景可取消并回到重开按钮。空局和终局可直接开始新局。
- **后台计算**：搜索和提示在后台运行，动作经过纯规则校验；计算超时后可重试。

五子棋先手执黑，使用 15 路棋盘。手机默认显示全盘；“放大”后可在棋盘内双向滑动，“定位最近一步”可查看局部，空局定位到中心，再点“全盘”返回。拖动棋盘不会落子。

点格棋封格得分后可连续画边，电脑也会完成自己的连续回合。

### 四子连线残局闯关

- **9 关训练**：一步取胜、守住对手一步胜着、两步必胜各 3 关；棋面由合法对局历史重放生成，所有符合目标的合法落点都可通关。
- **亲自完成解题**：两步题需在对手实际应手后完成最后一手；错着保留题面并解释原因，提示只标参考列，可自行选择是否采用。
- **自由选关与续题**：支持选关、重试、刷新续题，通关后手动进入下一关；记录“独立完成”或“参考完成”的最好结果，多标签完成不会互相降级。
- **手机与键盘适配**：手机进度常显，关卡列表可横向滑动；换关和刷新恢复时显示当前关，明确换关后焦点进入新题目标。

当前题的步骤保存在本标签。存储暂不可用时，本页保留已知成果并提示刷新后可能需要重做；下次通关会重试未保存的成绩，全部成功后提示消失。残局记录与电脑练习、24 点及好友房存档分开。

### 推箱子十关解谜

- **逐关规划**：10 张固定小棋面从 1 箱增加到 3 箱，每关都经独立求解器验证；箱子只能推，全部进入目标后才通关。
- **亲自操作**：棋盘或方向按钮聚焦时可用方向键 / WASD，也可点击方向按钮。撞墙、越界或连推两箱不会计步；悔棋同步回退步数和推箱次数。
- **手动选关**：进行中的关卡切换或重试需要确认，可用 Esc 取消；通关后仍留在原关，由玩家选择下一关。手机关卡轨道保持当前关可见。
- **进度与最佳成绩**：当前标签刷新后可重放未完成的尝试；每关记录经过完整合法通关轨迹验证的最佳步数，步数相同再比推箱次数。重试或换关不会抹去已有成绩。

<details>
<summary>推箱子存档与异常恢复</summary>

当前关卡及移动历史保存在本标签的 `sessionStorage`，各关最佳通关历史保存在 `localStorage`；与电脑练习、四子连线残局和 24 点的键分开。加载记录时严格重放已知关卡内的有界合法移动，成绩由实际通关轨迹推导，不采信单独保存的计数。不同成绩使用独立候选键，多标签交错写入后仍取最优，较差候选在确认更好成绩已保存后清理。存储损坏或暂不可用时仍能继续操作，页面保留已知成果并显示警告；恢复后可点击“重试保存”。

</details>

### 24 点单人练习

- **两种节奏**：不限时 10 题练习或 60 秒挑战；每组 10 道题均可解，牌面数字组合不重复。
- **算式编辑**：点牌输入数值，在光标位置编辑；支持按钮和快捷键撤销、重做，与在线对局共用编辑器。
- **即时反馈与提示**：错答保留算式，逐步提示展示一种可行解法；答对或查看答案后，手动进入下一题。
- **分项结果**：区分独立解出、参考解出和查看答案；支持暂停、恢复、再来一组。
- **计时与焦点**：挑战在题间持续计时，运行中隐藏页面或离开时暂停；恢复后等待手动继续。明确开始、继续或进入下一题后，焦点进入可操作的算式框或下一题按钮。

异步生成期间，用户移焦后不会被抢回焦点；离开已暂停或已结算的页面不会改写共享存档。首页根据当前浏览器的进度显示“继续练习”或“查看上组结果”，存档无效或共享库不可读时仍可打开练习。

练习入口支持浏览器前进 / 后退，保留原滚动、键盘焦点、房间邀请码及其他 URL 参数。会话连接中也能进入练习；若好友房随后恢复，页面提示并由玩家自行返回好友对局。

## 本地运行

环境要求：**Node.js 24.15.0+（24.x）**、**pnpm 11.19.0+**。仓库锁定的包管理器版本为 `pnpm@11.19.0`。

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

| 入口 | 地址 |
| --- | --- |
| Web | <http://127.0.0.1:5173> |
| 服务健康检查 | <http://127.0.0.1:3000/healthz> |

Vite 将 `/api` 和 `/socket.io` 代理到本地服务。首次启动时，服务端创建 SQLite 数据库并执行缺失迁移；需要单独运行迁移时，在服务停止后执行：

```bash
pnpm migrate
```

### 配置

从 [`.env.example`](.env.example) 开始配置。`.env`、SQLite 文件和 `storage/` 不应提交到仓库。

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `HOST` | HTTP 监听地址 | `0.0.0.0` |
| `PORT` | HTTP 端口 | `3000` |
| `DATABASE_PATH` | SQLite 数据库路径 | 服务进程工作目录下的 `storage/gamehall.sqlite` |
| `PUBLIC_ORIGIN` | 对外访问源 | 本地为 `http://127.0.0.1:5173` |
| `ALLOWED_ORIGINS` | 允许的逗号分隔源 | 开发环境包含本地 Web 源 |

<details>
<summary>局域网访问与 HTTP 连接说明</summary>

开发模式下，构建 Web 后可通过同一局域网的 `http://<本机 IP>:3000` 访问。需将该地址显式配置为 `PUBLIC_ORIGIN` 或列入 `ALLOWED_ORIGINS`；好友房按精确 Origin 校验，不使用通配 Origin。

- 纯 HTTP 响应不会要求浏览器将脚本升级到 HTTPS；生产和 HTTPS 请求保留原有 CSP 升级策略。
- 浏览器退化到 HTTP 轮询且请求不带 Origin 时，使用 `/api/session` 返回的 `socketProof` 与 HttpOnly 会话 Cookie 共同验证每次请求。
- `/api/session` 响应禁止缓存，证明不会放进连接 URL。
- 命令和动作 ID 使用安全随机数生成标准 UUID；局域网 HTTP 页面不能使用 `crypto.randomUUID()` 时，改用 `crypto.getRandomValues()`。缺少安全随机数源时显示明确错误，并停止发送命令。

</details>

## 技术架构

**React + Vite** · **Express + Socket.IO** · **TypeScript + Zod** · **SQLite** · **pnpm workspace**

```text
浏览器 React / Vite
        │ HTTP + Socket.IO
        ▼
Express / Socket.IO 服务
        │ 房间、会话、动作、事务、广播
        ├── packages/game-core   纯函数游戏规则
        ├── packages/protocol    Zod 协议与共享类型
        └── SQLite              房间、成员、消息、动作回执与对局状态
```

`packages/game-core` 提供八款游戏的纯规则引擎；服务端统一负责动作校验、版本推进、广播与恢复；前端根据共享快照渲染棋盘、牌桌和结算界面。

核心包另有独立的推箱子单人规则与 10 张固定小棋面，测试用独立求解器逐关验证可解；该玩法只在本地单人练习中使用，不增加好友房游戏种类。

| 目录 / 文件 | 职责 |
| --- | --- |
| [`apps/web`](apps/web) | React + Vite 前端、单人练习与后台搜索 |
| [`apps/server`](apps/server) | Express + Socket.IO 服务、房间与数据库 |
| [`packages/game-core`](packages/game-core) | 八款游戏的纯规则引擎 |
| [`packages/protocol`](packages/protocol) | 客户端与服务端共享的事件协议 |
| [`docs`](docs) | 验证流程与项目文档 |
| [`render.yaml`](render.yaml) | Render 单实例部署配置 |

`room:sync` 只接受成员的房间 ID，并在限流范围内重发权威房间、游戏和消息快照。访客会话超过有效期后会建立新身份，无法凭旧会话恢复原座位。

<details>
<summary>电脑搜索与棋局存档校验</summary>

四子连线、黑白棋和点格棋的电脑搜索复用纯规则，在独立 Worker 中以有界深度和节点数选择合法动作。战术判断覆盖四连胜负、黑白棋角位，以及点格棋封格得分、避免送出第三边和连续回合；四连检测复用规则核心。

各棋种的存档编解码彼此隔离，限制格式版本、大小和悔棋历史。读取时使用对应纯规则反序列化，核对单人局的回合、自然终局与比分。

| 棋种 | 额外校验 |
| --- | --- |
| 点格棋 | 保存最多 24 条实际画边轨迹，从先手逐步重放，核对悔棋前的人类回合快照 |
| 五子棋 | 保存最多 225 步完整轨迹，重放核对终局及最近最多 16 个悔棋快照，支持长局刷新继续 |

超限损坏记录只保留有界指纹，用于提示记录变化；跨标签原子比较由存储事务完成。

</details>

<details>
<summary>多窗口保存、冲突比较与旧存档迁移</summary>

练习页和首页以 IndexedDB 为共享存档源，在单次读写事务中按游戏比较修订，不依赖 Web Locks。`sessionStorage` 保存本标签即时草稿，用于刷新恢复；共享存储暂不可用时保留草稿，并提示当前保存范围。

**冲突比较**

- 棋类练习保留本标签棋盘，并排展示差异，由玩家明确选择使用共享棋局或保存当前棋局。
- 选择共享棋局前重读修订；另一窗口再次更新时先展示新预览，需再次选择。读取期间本地继续落子，不会被迟到结果覆盖。
- 24 点保留本标签进度草稿，包括已暂停或已结算的题组；刷新后仍能比较本标签与共享进度。
- 24 点冲突框并排显示阶段、题牌、草稿、提示和挑战剩余时间。共享更新只刷新预览；选择前再次核对版本，出现未见过的新版时先提示重新比较。

**迟到回执**

- 24 点事务提交回执超时后，以本次写入的唯一令牌核对。未确认时，将待核对令牌和即时草稿保存在 `sessionStorage`，刷新后继续确认。
- 四子连线、黑白棋和点格棋也用写前记录的唯一令牌核对迟到回执与刷新后的存档归属，避免将自己的提交误报成窗口冲突，或将残留旧草稿误报为已保存。

**旧记录迁移**

旧版 `localStorage` 记录仅在尚无 IndexedDB 存档时读取，首次成功保存后迁移，不双写旧存储。共享存储不可读时，旧记录和本标签草稿仍可恢复，并显示保存范围。

</details>

<details>
<summary>24 点题组生成与恢复校验</summary>

单人题组在 Web Worker 中生成并验算。10 题进度、算式草稿、提示状态和挑战剩余时间使用独立版本化存档。

恢复时校验真实牌 ID、题组不重复、可验证答案和作答记录，计时默认暂停。首页入口只读共享进度与本标签草稿；浏览器禁止存储时显示当前保存范围。

</details>

## 验证

按改动范围选择检查，所有交付 commit 完成后运行一次完整门禁：

| 命令 | 范围 |
| --- | --- |
| `pnpm verify:web` | 前端 lint、类型检查、测试和构建 |
| `python scripts/verify_local_fonts.py` | 检查本地 WOFF2、可变字重、界面字集与字体许可；需要 [字体工具](docs/assets/local-fonts.md) |
| `pnpm verify:core` | 游戏规则核心 lint、类型检查、测试和构建 |

## 游戏规则范围

| 游戏 | 当前规则范围 |
| --- | --- |
| 璀璨宝石 | 90 张发展卡、10 张贵族；2–4 人供应设置；保留、购买、黄金支付、贵族选择；15 分终局与平局处理 |
| 五子棋 | 15 × 15 棋盘；黑先、连续五子胜、无禁手、满盘和棋 |

| 黑白棋 | 8 × 8 棋盘；黑先、八方向夹子翻转；无合法步自动跳过；双方均无步或满盘时按棋子数结算；双方确认复赛后交换黑方 |
| 点格棋 | 4 × 4 个点、24 条边、9 个格子；封格每格得 1 分且继续回合；边全部画满后按分数结算；双方确认复赛后交换先手 |

德州扑克的奇数余数从庄家左侧分配；全体未淘汰玩家确认后发下一手，仅剩一名有筹码玩家时整局结束。游戏内筹码不对应现金或长期资产。

## 部署

项目提供 [`render.yaml`](render.yaml) 作为 Render 单实例 Web Service 配置。部署后可用 `/healthz` 检查服务状态。

默认配置适合临时试玩：免费实例会休眠，SQLite 位于实例本地且没有持久磁盘，重启、休眠或重新部署可能清空游客、房间和对局数据。

需要稳定保存数据时，应使用持久磁盘和单实例部署；未来若需横向扩容，应先将房间状态与动作回执迁移到可共享的数据服务。

## 设计边界

- 当前不包含账号系统、匹配、观战、排行榜、永久战绩、跨房私聊和支付能力。
- 实时连接、房间状态和 SQLite 由同一个服务实例承载；免费部署不具备高可用保障。
- 客户端提交动作，服务端决定规则结果并广播状态。
- 对局快照按玩法公开必要信息；璀璨宝石保留牌、德州扑克手牌等私有信息不会出现在其他玩家的视图中。
- 游戏资源只存在于当前房间和对局生命周期内，不支持充值、提现、跨房保存或形成长期资产。
